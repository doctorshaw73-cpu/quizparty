QUIZPARTY QUIZ GENERATOR — INSTRUCTIONS FOR AN AI MODEL
=========================================================

Paste everything below into an AI chat (ChatGPT, Claude, etc.) along with
a description of the quiz you want (topic, number of questions, audience,
difficulty, which question types to use, etc.). The AI should reply with
ONE valid JSON file matching the exact format below. Save that reply as a
.json file and import it into QuizParty via: Library -> Import.

=========================================================
YOUR TASK (give these instructions to the AI)
=========================================================

Generate a QuizParty quiz as a single JSON object. Output ONLY the raw
JSON — no markdown code fences, no commentary before or after, no
trailing commas, no comments. The JSON must be directly loadable with
JSON.parse().

TOP-LEVEL SHAPE
----------------
{
  "title": "string, the quiz's name",
  "questions": [ <question object>, <question object>, ... ]
}

Do not include an "id" field — QuizParty assigns one on import.
Do not include a top-level "media" field unless you are specifically
embedding real media (see MEDIA section below) — in almost every case
you should leave it out entirely.

EVERY QUESTION HAS THESE COMMON FIELDS
----------------------------------------
{
  "type":   one of: "mc" | "tf" | "order" | "typed" | "scramble" |
                     "guesssong" | "guesssound" | "blur" | "zoom" |
                     "silhouette" | "puzzlereveal" | "slider" | "poll" |
                     "scale" | "wordcloud" | "open" | "imagepin"
  "text":   the question text, plain string, max 200 characters
  "time":   seconds on the clock. Use one of: 5, 10, 20, 30, 60, 90
            (other numbers work but these are the ones the app's own
            editor UI offers, so stick to them unless told otherwise)
  "points": "standard" (normal points) | "double" (2x points) |
            "none" (ungraded / ungraded-by-design types should use this)
  "media":  { "image": null, "video": null, "audio": null }
            — leave all three null unless you are embedding real media
            (see MEDIA section). Do not invent fake ids or URLs here.
  "videoEmbed": null, or an object/string embedding an external video
            (YouTube, Facebook, or any other site) — see VIDEO EMBED
            section below. This one you CAN generate confidently without
            any binary data, since it's just a URL.

  ... plus the type-specific fields listed below, one block per type.
}

Every question also needs AT LEAST ONE correct answer marked where the
type has a "correct" concept — see each type's rules below.

=========================================================
THE 17 QUESTION TYPES — EXACT FIELDS FOR EACH
=========================================================

1) "mc" — Multiple choice (graded)
   "answers": [ { "text": "string, max 100 chars", "correct": true|false }, ... ]
   Rules: 2 to 4 answers. At least 2 must have non-empty text. At least
   one must have "correct": true. More than one may be correct.

2) "tf" — True / False (graded)
   "correct": true | false   (true = "True" is the correct answer)
   No other fields.

3) "order" — Order / puzzle (graded)
   "items": [ { "text": "string, max 100 chars" }, ... ]
   Rules: 2 to 6 items. The CORRECT ORDER is simply the order you list
   them in this array — item 0 must come first, item 1 second, etc.

4) "typed" — Typed answer (graded)
   "accepted": [ "string, max 100 chars", ... ]
   Rules: 1 to 10 accepted answers. Matching is case-insensitive and
   exact after trimming whitespace (no fuzzy matching) — so list every
   reasonable spelling/phrasing you want accepted, e.g.
   ["Paris", "paris, france"].

5) "scramble" — Word Scramble (graded)
   "accepted": [ "string, max 100 chars", ... ]  (identical shape/rules to
   "typed" above, including the phrasing-variants trick)
   The host screen automatically shuffles the FIRST accepted answer's
   letters (word boundaries/spacing are kept, so a multi-word answer still
   shows as separate scrambled words) — you don't generate the scrambled
   form yourself, the app does it. Pick a short, single-concept answer
   (one word or a short phrase) — a long sentence makes a messy scramble.

6) "guesssong" — Guess the Song (graded, REQUIRES a real attached audio clip)
   "accepted": [ "string, max 100 chars", ... ]  (same shape/rules as "typed")
   "audioClipSeconds": integer 1-30, optional (null/omitted = play the
   whole file). The host clicks a "Play clip" button that plays the
   attached audio, auto-stopping after this many seconds if set.
   IMPORTANT: unanswerable without a real audio file attached via
   "media.audio" (see MEDIA section) — same rule as "imagepin" needing an
   image. Do not generate this type unless you're also embedding real
   audio, or are explicitly telling the human to attach a clip afterward.

7) "guesssound" — Guess the Sound (graded, REQUIRES a real attached audio clip)
   Identical fields/rules to "guesssong" — same mechanic, used for a sound
   effect (an animal, an object, an event) instead of a song.

8) "blur" — Blurred Picture (graded, REQUIRES a real attached image)
   "accepted": [ "string, max 100 chars", ... ]  (same shape/rules as
   "typed"/"scramble") — players type what the picture shows.
   The host screen shows the attached image starting heavily blurred,
   then smoothly sharpens to fully clear over the question's own time
   limit ("time" field) — no separate reveal-duration field needed.
   IMPORTANT: unanswerable without a real image attached via
   "media.image" (see MEDIA section) — same rule as "imagepin".

9) "zoom" — Zoomed-In Picture (graded, REQUIRES a real attached image)
   Identical fields/rules to "blur". The host screen instead starts
   zoomed way into the image (an extreme close-up) and smoothly zooms
   back out to the full picture over the question's time limit.

10) "silhouette" — Silhouette Reveal (graded, REQUIRES a real attached image)
   Identical fields/rules to "blur". The host screen instead starts with
   the image as a solid black silhouette and smoothly fades up to full
   brightness/color over the question's time limit.

11) "puzzlereveal" — Puzzle Piece Reveal (graded, REQUIRES a real attached image)
   Identical fields/rules to "blur". The host screen instead covers the
   image with a grid of opaque tiles that disappear one at a time, in a
   random order, timed so the last tile clears right as the question's
   time limit runs out.

12) "slider" — Slider / numeric (graded)
   "min": number, "max": number (min must be less than max)
   "step": number (the slider's increment, e.g. 1, 0.5, 5)
   "correct": number (must be between min and max)
   Players are scored within a small automatic tolerance around "correct"
   — you don't need to add any tolerance yourself.

13) "poll" — Poll (ungraded, shows live distribution; use "points": "none")
   "options": [ { "text": "string, max 100 chars" }, ... ]
   Rules: 2 to 6 options. No "correct" concept at all.

14) "scale" — Scale / rating (ungraded; use "points": "none")
   "min": integer, "max": integer (max - min + 1 must be <= 8)
   "lowLabel": "string, max 30 chars, optional, e.g. 'Strongly disagree'"
   "highLabel": "string, max 30 chars, optional, e.g. 'Strongly agree'"
   No "correct" concept — it just collects a rating distribution.

15) "wordcloud" — Word cloud (ungraded; use "points": "none")
   No extra fields at all. Players each submit one short word/phrase;
   the host screen aggregates them into a word cloud.

16) "open" — Open-ended (ungraded; use "points": "none")
   No extra fields at all. Players each write a free-text response,
   listed on the host screen for discussion.

17) "imagepin" — Image pin (graded, REQUIRES a real attached image)
    "pin": { "x": number 0-1, "y": number 0-1 }   <- the correct spot,
             as a fraction of image width/height (0,0 = top-left,
             1,1 = bottom-right, 0.5,0.5 = dead center)
    "tolerance": number 0.01-0.5 (how close counts as correct; 0.08 is
                 a sensible default — smaller = stricter)
    IMPORTANT: this type is unanswerable without a real image attached
    via "media.image" (see MEDIA section). Do not generate an "imagepin"
    question unless you are also embedding a real image, OR you are
    explicitly telling the human they must attach one manually in the
    editor afterward (QuizParty will refuse to host the quiz otherwise).

NOT CURRENTLY SUPPORTED — do not invent fields for this: there is no way
for an answer OPTION itself to be a picture (e.g. "mc"/"poll" choices are
always text only, never one image per choice, and there's no way to make
a picture itself the thing a player picks as their answer). Progressive
image-reveal effects (blur, zoom, silhouette, puzzle-tile) ARE supported
— see types 8-11 above — but in all of them the image is the PROMPT, and
the player's answer is still always typed text, never a picture tap/pick
(except "imagepin", which is a single tap-the-spot-on-the-image type, not
a multiple-choice-of-images type).

=========================================================
VIDEO EMBED (YouTube / Facebook / any other site) — THE EASY ONE
=========================================================

If the human gives you a video URL (or a well-known video you can
confidently name a real, correct URL for), you CAN generate this field
directly — it's just a URL/small object, no binary data involved at all.
This is different from the MEDIA section below (images/audio/your-own
video files), which really does need real file bytes you can't invent.

  "videoEmbed": { "provider": "youtube", "ref": "dQw4w9WgXcQ", "start": 30, "end": 90 }

  "provider": "youtube" | "vimeo" | "facebook" | "custom"
    - "youtube": "ref" is the 11-character video id (from a URL like
      youtube.com/watch?v=<id> or youtu.be/<id>). "start"/"end" (seconds,
      integers, optional) trim it to just a clip, and playback halts
      itself at "end" — reliable, documented YouTube behavior.
    - "vimeo": "ref" is the numeric video id (from vimeo.com/<id>).
      "start" really does seek to that point (Vimeo's own documented
      #t= link format). "end" covers the screen once the clip length has
      elapsed, but can't make the underlying Vimeo player actually stop —
      good enough for the audience, not a true pause.
    - "facebook": "ref" is the full Facebook video page URL. Facebook has
      no documented way to seek OR trim at all — don't set start/end for
      it, they're dropped entirely rather than silently doing nothing.
    - "custom": "ref" is the real embeddable URL for ANY other site
      (Yandex, etc.) — typically what that site's own "Share -> Embed"
      feature gives you. Only use this if you (or the human) actually
      have that real URL; never invent one. start/end are dropped for
      this provider too (no standardized way to seek/trim an arbitrary
      unknown platform's embed) — the full video always plays from its
      own beginning.

  A plain string also works in place of the object (the app detects the
  provider itself) — simplest when you don't need clip trimming:
    "videoEmbed": "https://youtu.be/dQw4w9WgXcQ"

  Leave "videoEmbed": null (or omit it) when there's no video to embed.

  IMPORTANT — this is an EMBED, not a download: the video streams live
  from YouTube/Facebook/whatever site at show-time, nothing is copied or
  stored. Never invent/guess a video URL as if it definitely exists and
  is the right one — if you're not confident a specific real video exists
  at that URL, say so to the human instead of fabricating one.

=========================================================
MEDIA (images / your-own video files / audio) — READ THIS CAREFULLY
=========================================================

QuizParty quizzes can also carry embedded images, your own video files,
and audio (as opposed to the VIDEO EMBED above, which links to a video
hosted elsewhere). Whether an AI can supply real bytes for these depends
entirely on what kind of AI you're talking to:
  - A plain text/chat model (ChatGPT, Claude, etc. in normal chat) cannot
    generate real image/video/audio binary data in its reply — it can
    only produce text, so it cannot invent a real file here.
  - A generation tool that actually produces files — an image model via
    ComfyUI/Stable Diffusion, an audio-generation model, etc. — CAN
    produce a real file. That's a genuinely different capability from a
    text chat reply.
Either way, there are two honest ways to actually get that media into a
quiz:

OPTION A (recommended default — use this whether or not real media exists
yet, including media a generation tool like ComfyUI made):
Leave every question's "media" as { "image": null, "video": null,
"audio": null }, generate the quiz text/questions only, and tell the
human which question(s) they should attach media to afterward and what
kind of image/video/audio would fit well. They (or you, working through
ComfyUI or similar separately) produce the actual file, then it gets
attached inside the QuizParty editor itself (an "Image" / "Video" /
"Audio" button per question, a normal file picker) — no JSON editing
needed. This is the realistic path for anything but a tiny file: even a
real AI-generated image easily becomes multiple megabytes of base64 text,
which is impractical to paste through a chat interface's input limits.

OPTION B (only for a SMALL file, and only once you actually have its real
bytes as base64 — e.g. the human pasted "here is my logo, base64:
iVBORw0KG..." or an image-generation tool's own output): you may embed it
directly. If you do, the quiz needs a top-level "media" map alongside
"questions", and each question's media field points at a key in it:

  {
    "title": "...",
    "questions": [
      {
        "type": "mc", "text": "...", "time": 20, "points": "standard",
        "media": { "image": "img1", "video": null, "audio": null },
        "answers": [...]
      }
    ],
    "media": {
      "img1": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
    }
  }

  Rules for Option B:
  - The media map's keys are arbitrary short ids you invent (e.g. "img1",
    "clip1") — they just have to match what each question's media field
    references.
  - Each value MUST be a proper data: URL (data:<mimetype>;base64,<data>)
    containing the file's real bytes — never a plain http(s):// link
    (QuizParty does not fetch remote URLs; everything is embedded).
  - Size/type limits per kind — anything outside these will be rejected
    on import, so don't exceed them:
      image: PNG, JPEG, GIF, or WEBP only, up to 5 MB
      audio: MP3, OGG, WAV, or WEBM only, up to 15 MB
      video: MP4, WEBM, or OGG only, up to 50 MB
  - A question's "media.image"/"media.video"/"media.audio" can each
    independently be null or a media-map id — a question can have all
    three, just one, or none.

In practice: for almost every request, use Option A, and use VIDEO EMBED
above (not this MEDIA section at all) whenever a video from YouTube,
Facebook, or elsewhere is what's actually wanted — it needs no file data
and no size limits apply. Only use Option B here if you have real, small
file bytes in hand.

=========================================================
HOW TO USE THE AI'S OUTPUT
=========================================================
1. Copy the AI's reply (it should be nothing but the JSON).
2. Save it as a plain text file with a .json extension, e.g. my-quiz.json
3. In QuizParty: Library -> Import -> select that file.
4. If it imported successfully it'll appear in your library — click Edit
   to review/tweak it, attach any media the AI told you to add, or Host
   it directly.
5. If import fails, the error message will say why — the most common
   causes are: missing required fields for a type (see above), a typo in
   "type" (must exactly match one of the 17 listed), or the AI having
   added markdown formatting (```json fences) around the JSON that needs
   to be stripped out first.
